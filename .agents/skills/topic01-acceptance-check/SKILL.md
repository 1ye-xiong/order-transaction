# 验收检查 Skill：题目 01 逐项验收（topic01-acceptance-check）

## 用途
依据《Go 项目业务场景题》题目 01 原始题面，对最终版本逐项核对实现与证据，输出可定位的验收结论。

## 触发场景
- 验收 Agent 会话开始时（必须读取原始题面与对应版本代码）。
- 开发完成、提交 PR 前的自检。

## 输入
- 原始题面（题目 01 全文）。
- 被验收版本的代码、测试输出、覆盖率结果、部署/冒烟记录。

## 执行步骤
1. **业务范围核对**：对照题面"需要完成的业务范围与规则"R1~R8 逐条打勾，每条附代码证据（文件:行号）或页面操作路径。
2. **五组场景核对**：S1 正常成交、S2 缺货与弃单（并发 20 请求）、S3 售前退款（首次退款失败、再次成功）、S4 迟到支付、S5 操作竞争（并发/重复/越权），逐条确认有可操作入口与持久化结果。
3. **异常路径核对**：验签失败、金额不符、未知订单、重复通知、超时关闭后迟到通知、退款失败重试、发货受限——每条必须有查询到处理结果的途径。
4. **测试证据核对**：整体与核心包单元覆盖率 ≥85%（原始输出）；并发场景有可重复执行的验证；竞态检测通过。
5. **部署证据核对**：流水线包含质量检查→覆盖率门禁→构建→部署→健康检查→冒烟；部署版本与验收版本一致；回滚方案已说明。
6. **真实性核对**：异常记录未被直接改状态消除；模拟渠道未被宣称成真实第三方。

## 输出格式
```text
[topic01-acceptance-check 验收报告]
- 被验收版本：<提交哈希>
- R1~R8：逐条 通过/不通过 + 证据位置
- S1~S5：逐条 通过/不通过 + 演示路径/测试名
- 覆盖率：整体 <x>%，核心包 <逐包>% （门禁 ≥85%）
- 部署：通过/不通过 + 流水线记录位置
- 最终结论：ACCEPT / REJECT（不通过项清单）
```

## 失败处理
- 任何必查项缺证据即该项"不通过"；不得以口头声明代替证据。
- REJECT 结论交回学生安排修复，修复后重跑受影响检查。

## 完成标准
所有条目均有结论与证据位置，最终结论为 ACCEPT 或明确的 REJECT 清单。


## v2补充检查与证据边界

版本v2，2026年11月12日，基于项目原有自编草稿修订，不声称原始作者身份或创建时间已核验。原始题面和通用要求路径见docs/agents/README.md，优先读取原始来源。

输入必须包括实际提交、工作区差异或文件摘要、当前任务、AGENTS版本、相关原始输出。没有代码或服务时只能执行文件或设计审查，不能输出系统PASS。缺输入标证据不足，未执行标未执行；只有充分运行证据才可给运行验证通过。

除原有六步，逐项核对十条通用要求：七阶段真实提交、三个独立会话读取原题和对应代码、学生审核与纠错；AGENTS历史和实际加载；两个Skill各七项与配置、调用、检查修正复检或未发现说明、全部Skill使用总结；Markdown全量可见导出、按时间排序JSON或JSONL和缺失范围、一页AI说明。

质量核对整体及每个核心实际Go包单元语句覆盖率≥85%，而非多个服务合并总数；自编HTTP及数据库层不自行排除；生成与第三方排除清单，其他例外教师事先批准；格式、vet、必要接口数据库集成、可重复并发及race均保存原始证据。核查可维护性、错误处理与日志截图脱敏。

Git核对MCP建仓工具请求返回时间、dev/01全阶段历史、main保护读取、feat/fix在r17te9真实meegle编号内容核验、规范提交、PR检查和保留源提交合并。核对主分支实际发布提交重新门禁及制品、版本、真实教学地址、流水线运行、健康与业务冒烟、回滚或首次撤销。当前CI文件存在不等于部署成功。

核对学生本人讲解与效果视频、五组场景、实际视频时间目录、最终版本一致、当日群提交及教师访问权限。不能代造视频、群消息或完成日期。

输出R1至R8、S1至S5、通用G1至G10逐项矩阵及证据内容，不只列一个链接。阶段核查与整题验收分别出结论；任一一票否决项未满足不得ACCEPT。完成标准补充为所有通用要求也有结论和真实依据，而非仅业务八条。
