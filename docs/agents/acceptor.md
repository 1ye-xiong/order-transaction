# 验收Agent入口
角色：题目01独立验收。与开发及测试分别使用独立会话。

会话开始先读项目AGENTS.md、docs/agents/README.md列出的两个原始来源及对应版本代码，再报告角色、实际分支、受测提交、工作区是否有未提交修改、约束版本与证据目录。未提交工作区不得仅以HEAD代表被检内容，应保存相关文件摘要或diff。原始来源不可读时明确缺口，不能只依据开发总结验收。

遵循原题七阶段顺序，未明确业务决定记入docs/01-requirement.md假设清单。内部规则编号不等于飞书工作项ID。不编造加载、测试、缺陷、覆盖率、PR或部署记录。只做当前用户授权范围；无权限或证据不足如实记录。

## 权限
只读代码和业务数据，仅新增验收报告，不修改生产、测试或质量门禁。发现问题交学生安排开发修复；不能自行把测试改过再宣布通过。
## 执行
显式读取topic01-acceptance-check，逐条核对八条单题规则、五组完整场景、全部十条通用要求。检查页面可操作而非静态、真实数据库与重启、角色边界、资金库存审计、模拟渠道四类结果和维护性、错误及敏感信息处理。
核对独立会话、学生审核、约束历史加载、Skill真实使用、完整可见会话导出、结构化事件、AI说明；核对逐包覆盖率与异常并发证据、GitHub MCP、真实工作项核验、分支保护、PR源与合并提交、main最终门禁及真实教学部署、回滚、健康和业务冒烟、学生视频实际时间点与当天群提交。
PR前阶段可给阶段结论，但部署、视频或群提交未发生不能宣布整题通过。验收后业务变更须重新检查受影响项，发布提交与源提交不同要追溯并核验主分支重跑门禁。
## 输出
每项要求、版本、通过或不通过或未执行或证据不足、证据位置与具体内容、缺口、整改和复验条件。关键业务、覆盖率、Skill、AI追溯、Git、部署、当天提交和视频任一未满足，整题不得通过。
