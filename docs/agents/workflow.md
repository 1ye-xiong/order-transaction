# 开发 → 测试 → 验收

## 角色入口

三个完整角色文件位于 `.agents/developer.agent`、`.agents/tester.agent`、`.agents/acceptor.agent`，依次负责开发、测试、验收。文件使用 UTF-8 文本，包含职责、权限、输入、执行步骤、业务检查、交接模板与完成条件。
每次在独立会话中显式读取对应文件并执行。`.agent` 是本项目要求的角色文件扩展名，不声称任何客户端会自动识别或注册；文件存在也不代表角色已运行或通过验收。上次误加的 `.codex/` TOML配置已移除。

启动开发：`请读取 .agents/developer.agent，按其中流程完成本次开发任务：<具体任务>。`

启动测试：`请读取 .agents/tester.agent，独立测试交接版本：<提交与工作区摘要>，交接材料：<路径>。`

启动验收：`请读取 .agents/acceptor.agent，独立验收最终版本：<版本>，测试及交付证据：<路径>。`

## 顺序与退回

1. 开发：读取原始需求，实现当前授权任务，完成自查并交接明确版本。
2. 测试：独立读取需求与代码，执行测试。发现缺陷退回开发；修复后复测。测试通过才交验收。
3. 验收：独立检查最终版本、原题及原始测试证据，逐项出具结论。失败退回开发，之后重新经过测试与验收。

三个角色使用独立上下文，不以同一会话切换称谓冒充独立检查。不要求同时运行；没有具体业务任务时只配置角色，不自行启动业务开发、全项目测试或验收。

## 每次交接必填

- 当前任务、原始需求来源、需求及假设编号。
- 分支、提交、未提交差异或文件摘要；接收方先核对版本。
- 本次变更、运行方法、隔离数据准备方式。
- 实际执行的检查、退出结果、原始输出位置；未执行检查和原因。
- 缺陷、风险、复测记录及下一环节待核对项。
- 角色、真实会话标识和时间；不可获取的字段如实标记。

版本变化后，受影响的测试和验收结论必须重新核查。本文仅定义后续流程，不补造历史执行证据。
