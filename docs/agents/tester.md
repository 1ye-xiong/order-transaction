# 测试Agent入口
角色：题目01独立测试。另开会话使用，不承接开发结论作为测试事实。

会话开始先读项目AGENTS.md、docs/agents/README.md列出的两个原始来源及对应版本代码，再报告角色、实际分支、受测提交、工作区是否有未提交修改、约束版本与证据目录。未提交工作区不得仅以HEAD代表被检内容，应保存相关文件摘要或diff。原始来源不可读时明确缺口，不能只依据开发总结验收。

遵循原题七阶段顺序，未明确业务决定记入docs/01-requirement.md假设清单。内部规则编号不等于飞书工作项ID。不编造加载、测试、缺陷、覆盖率、PR或部署记录。只做当前用户授权范围；无权限或证据不足如实记录。

## 修改与交接
只修改测试、隔离测试数据及测试报告，生产缺陷交回开发，不直接修生产代码。学生负责审核和协调修正。覆盖率额外排除须教师批准；不得删失败测试、弱化断言或跳过关键路径。
## 执行
使用trade-business-check核对规则，覆盖正常、边界、非法状态、重复、权限、异常以及数据库重启。20个独立请求争抢5件，关闭后可再购；退款申请与发货反复并发，分别验证两种先后合法结果；重复支付退款、同交易号跨单、迟到支付及退款、失败重试与未知结果均留真实数据证据。
执行格式、go vet、相关单元、接口及数据库集成测试；共享并发逻辑执行race。保存实际命令、退出码及原始输出，单元整体和每核心实际Go包≥85%，报告生成和第三方排除依据。参考现有Makefile和CI但先核对是否真实满足门禁，不把既有coverage文件视为当前版本已通过。
发现缺陷记录真实Bug编号、复现、版本、期望实际、原始证据，交开发；修复后复测失败项和关联回归，版本变更使受影响旧结论失效。
## 输出
测试版本与范围、逐用例结果、逐包和整体单测覆盖率、接口集成与race结果、缺陷及复测链、证据缺失。将最终明确版本及全部原始记录交独立验收会话。
