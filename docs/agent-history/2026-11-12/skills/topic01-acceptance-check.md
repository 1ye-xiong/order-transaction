# 验收检查 Skill：题目 01 逐项验收（topic01-acceptance-check）

## 用途
依据《Go 项目业务场景题》题目 01 原始题面，对最终版本逐项核对实现与证据，输出可定位的验收结论。

## 触发场景
- 验收 Agent 会话开始时（必须读取原始题面与对应版本代码）。
- 开发完成、提交 PR 前的自检。

## 输入
- 原始题面（题目 01 全文）。
- 被验收版本的代码、测试输出、覆盖率结果、部署/冒烟记录。

## 执行步骤
1. **业务范围核对**：对照题面"需要完成的业务范围与规则"R1~R8 逐条打勾，每条附代码证据（文件:行号）或页面操作路径。
2. **五组场景核对**：S1 正常成交、S2 缺货与弃单（并发 20 请求）、S3 售前退款（首次退款失败、再次成功）、S4 迟到支付、S5 操作竞争（并发/重复/越权），逐条确认有可操作入口与持久化结果。
3. **异常路径核对**：验签失败、金额不符、未知订单、重复通知、超时关闭后迟到通知、退款失败重试、发货受限——每条必须有查询到处理结果的途径。
4. **测试证据核对**：整体与核心包单元覆盖率 ≥85%（原始输出）；并发场景有可重复执行的验证；竞态检测通过。
5. **部署证据核对**：流水线包含质量检查→覆盖率门禁→构建→部署→健康检查→冒烟；部署版本与验收版本一致；回滚方案已说明。
6. **真实性核对**：异常记录未被直接改状态消除；模拟渠道未被宣称成真实第三方。

## 输出格式
```text
[topic01-acceptance-check 验收报告]
- 被验收版本：<提交哈希>
- R1~R8：逐条 通过/不通过 + 证据位置
- S1~S5：逐条 通过/不通过 + 演示路径/测试名
- 覆盖率：整体 <x>%，核心包 <逐包>% （门禁 ≥85%）
- 部署：通过/不通过 + 流水线记录位置
- 最终结论：ACCEPT / REJECT（不通过项清单）
```

## 失败处理
- 任何必查项缺证据即该项"不通过"；不得以口头声明代替证据。
- REJECT 结论交回学生安排修复，修复后重跑受影响检查。

## 完成标准
所有条目均有结论与证据位置，最终结论为 ACCEPT 或明确的 REJECT 清单。
