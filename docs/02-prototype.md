# 题目 01 原型设计说明

原型为网关直接服务的轻量 HTML 页面（`web/` 目录，原生 JS + fetch，可点击操作）。
入口：`http://127.0.0.1:8080/`。所有页面共用登录框（预置账号见下），身份保存在 localStorage，
后端一律从 JWT 识别身份，页面传入的用户编号无效（防越权演示点）。

## 页面与状态说明

### 1. 商品与订单页（买家，/page/buyer）
- 商品列表：商品名、单价（分）、可售数量；可售 0 或已下架时按钮置灰。
- 下单：选商品、数量 1~2；失败（缺货/下架）时展示失败原因。
- 我的订单：状态、金额、运单信息；操作列按状态展示——待付款【取消】【付款】、待发货【申请退款】、
  已退款/已发货/已关闭展示结果与原因。
- 付款按钮触发渠道受理；渠道行为（成功/失败/超时/重复/迟到）在渠道控制台配置，
  通知结果在订单状态与"处理记录"中体现。

### 2. 仓库待发货页（/page/warehouse）
- 待发货订单列表（仅 PAID 状态）；对退款申请中订单不展示发货按钮，返回受限原因。
- 发货登记：填承运方 + 运单号；重复发货返回"已发货"错误。

### 3. 客服处理页（/page/cs）
- 退款审核列表：REFUND_REQUESTED 订单，同意/拒绝必须填写原因。
- 退款失败待处理：REFUND_FAILED 与异常支付（迟到支付）列表，可发起/重试退款。
- 每条记录展示历史处理原因（拒绝原因、失败原因），不可直接改订单状态。

### 4. 运营核查页（/page/ops）
- 商品可售数量、上下架/调价/补货操作。
- 交易汇总：已收款、已退款、各状态订单数。
- 订单流水核查：按订单号查收款、退款、发货、关闭、异常处理记录（只读）。

### 5. 模拟支付渠道控制台（/page/channel）
- 全局行为开关：通知次数（重复通知）、通知延迟（秒）、退款第 N 次起成功、本次支付直接失败/超时不通知。
- 渠道流水：受理的每笔支付与退款（金额、渠道交易号、结果），用于核对"重复通知不重复记款"。

## 异常状态展示清单

- 缺货/下架下单失败原因；取消与超时关闭结果；验签失败/金额不符/未知订单的处理结果记录；
  迟到支付进入异常列表；退款失败保留待处理；发货受限原因（退款中/已退款/已发货）；
  越权操作（他人订单）返回 403 明确提示。
